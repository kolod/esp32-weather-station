# Contract: Emulator Control Endpoints (`/emu/*`, mgmt port)

Emulator-only surface — **does not exist on the device** and must never be
called by `mgmt.js`/`portal.js`. Namespaced under `/emu` to guarantee no
collision with device routes. Served on the management port (8080).

## `GET /emu/scenario` → 200 `application/json`

Current scenario state:

```json
{
  "join_outcome": "success",
  "ota_outcome": "success",
  "sensor_valid": true,
  "time_synced": true,
  "wifi_connected": true,
  "storage_free_kb": 1024
}
```

## `PUT /emu/scenario`

JSON patch — any subset of the fields above. Unknown keys or invalid values → `400`
`{"error":"invalid_scenario","field":"<name>"}`. Success → `200` with the full
updated scenario (same shape as GET). Changes apply to subsequent requests;
in-flight join/OTA sessions keep the outcome they started with.

Valid values:

| Field | Values |
|-------|--------|
| `join_outcome` | `"success"`, `"auth"`, `"not_found"` |
| `ota_outcome` | `"success"`, `"invalid_image"`, `"write_error"` |
| `sensor_valid`, `time_synced`, `wifi_connected` | boolean |
| `storage_free_kb` | integer ≥ 0 |

## `GET /emu` → 200 `text/html`

Minimal self-contained control page (inline HTML/JS generated by the script, no
external assets, no framework): renders the scenario fields as selects/checkboxes,
loads state via `GET /emu/scenario`, applies changes via `PUT /emu/scenario`.
Purely a convenience wrapper over the JSON endpoint.

## CLI equivalents (initial state)

```text
--join-outcome {success,auth,not_found}
--ota-outcome {success,invalid_image,write_error}
--sensor-invalid          (sets sensor_valid=false)
--time-not-synced         (sets time_synced=false)
--wifi-disconnected       (sets wifi_connected=false)
--storage-free-kb N
--history-hours N         (default 24)
--mgmt-port N             (default 8080)
--portal-port N           (default 8081)
--no-browser              (suppress FR-014 auto-open)
```
